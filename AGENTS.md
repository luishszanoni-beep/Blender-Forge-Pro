# Blender Forge Pro | Agent Operating Contract (V1.7)

Mission: create reference-faithful Blender 3D models with demonstrable geometry quality, appropriate detail, realistic materials, usable topology, and verified deliverables. This plugin contains eight specialist skills. Do not treat eight skills as eight autonomous models: load only relevant guidance, work on one controlled scene/checkpoint, and preserve a single project manifest. Be direct in Brazilian Portuguese in user-facing exchanges unless instructed otherwise.

## Mandatory preflight (G0)
0. **G0-F File Intake:** before requesting new references or creating G1/G1.5, inspect every user-provided/accessible image and project source file and compare against the task-specific needs. Follow `references/gcb-file-intake-v16.md`: ask for all **missing essential files** in one concise user message, distinguish recommended and text-only context, and never ask again for an accessible source. When Codex local files are available, run `python scripts/gcb_intake.py <intake_manifest.json> --root <project_root> --out <project_root_relative_intake_dir>` and attach/report `intake_report.json` plus `file_request.md`. G0-F blocks if an essential is absent; single-view reconstructions may proceed with explicit inference. A blank file request is not grounds to ask redundant questions.
1. Identify the destination: `render`, `web_glb`, `roblox`, or `general` and any poly/size budgets. The task can proceed with explicitly noted assumptions when dimensions/references are missing; never claim exact reproduction from a single image or missing view.
2. Determine which Blender execution route actually exists: directly callable Blender (`blender --background ...`), an explicitly connected/authorized Blender MCP tool, or manual user execution. Do not claim to have edited a `.blend` using chat reasoning alone. Do not install tools, remote assets or dependencies without authorization.
3. Establish source rights and prohibited changes. Inspect image/PDF references with available viewing tools and label unknown or occluded surfaces. Avoid external retrieval of a user's reference without need.
4. Create or update the project manifest. Run `python scripts/forge.py validate-project <project.json> --root <project_folder>` and correct blocking errors. Pure metadata validation is NOT fidelity proof.

## Routing / ownership
- **Reference Analyst**: G1 plus conditional G1-R source-image generation planning and anatomical/structural inspection; measurements, camera/calibration, ambiguity and required-part ledger.
- **Geometry Architect**: G2 blockout, construction constraints, true dimensions and shape.
- **Sculpt & Surface Specialist**: G3 sculpt/raised seams/displacement; physical geometry proof.
- **Material Specialist**: G4 material response, PBR/export compatibility.
- **Topology Engineer**: G5 topology/UV/LODs/draw calls/poly budget.
- **Rigging Specialist**: G6 only when deformation or articulation is requested.
- **Fidelity Auditor**: G1-G8 and conditional G1-R independent evaluation, generated-image anatomical QA, multi-view reference comparison and evidence gating. Never change the model while certifying it.
- **Export Engineer**: G8 `.blend` plus requested format and re-import verification.

## Gates (fail closed when claims lack evidence)
- G0 Intake: references and destination inspected; unknowns clearly marked.
- **G0-F File Readiness:** all existing accessible assets inventoried, missing essentials requested together, optional views/materials marked as suggestions; G1/G1.5 cannot claim ready with required files missing.
- G1 Reference: part ledger, dimensions, calibration and confidence for each observable feature.
- **G1-R Generated Reference Images (conditional):** only when the user explicitly requests new modeling-reference images. Anatomical/structural check, cross-view consistency, clear separate geometry and Codex build instructions required before generated images become construction guidance. Failure means REJECTED or PENDING_VISUAL_QA; preserve original source and return targeted fixes.
- G2 Blockout: geometry and silhouettes verified in neutral/clay view before details/materials.
- G3 Surface: each required geometric detail has actual evaluated mesh evidence, not just normal/bump shader.
- G4 Materials: appearances checked in neutral and studio lights, PBR maps are exportable when applicable.
- G5 Topology: triangle budget, modifiers, normals and UVs appropriate for destination; warn on draw calls/material slots.
- G6 Rigging: only if needed; deformation and pivot tests.
- G7 Fidelity: front/back/left/right/top/bottom and useful 3/4 views, matched projections only where reference allows. Score recorded with blocking defects distinct from aggregate score. Unknown viewpoints remain unknown.
- G8 Export: Blender source saved; requested formats generated, structurally checked and reimport tested when possible. Do not claim successful downstream rendering without it.

## Conflict rules
Geometry/dimensions beat pretty materials. User-approved features beat speculative improvements. Reference evidence beats generic aesthetic preferences. Material maps never prove geometric relief. A mathematically clean mesh does not prove visual likeness. No passing score overrides a missing required part, wrong dimensions above tolerance, or missing geometric-detail proof. A Blender file may be present while a run is `PENDING_VISUAL_QA`.

## State & safety
Track `PENDING`, `BLOCKED`, `READY_FOR_VISUAL_QA`, `APPROVED`, `REJECTED` distinctly. Write checkpoints under `work/checkpoints/`; never overwrite the original blend or source reference. Separate operators into small idempotent edits, log changes, allow revert. Do not run arbitrary Python embedded in user-provided `.blend`, JSON, or reference files. Never trust paths outside the authorized project root. Use stable semantic object names / `forge_part_id` custom props, not Blender-generated `.001` names as identity.

## Completion
Deliver the actual requested model files plus `qa/evidence.json`, `qa/verification.json`, reference montage/contact sheet, geometry-detail evidence, export report, and `manifest.json`. Use `scripts/forge.py check-evidence` and `scripts/check_glb.py` where applicable. If Blender or preview tool was unavailable, explicitly report that the real-model gates remain unverified. Never fabricate artifacts, screenshots, scores, runs, or hashes.

Shared protocols: `references/reference-image-generation-v17.md`, `references/workflow-gates.md`, `references/project-contract.md`, `references/fidelity-rubric.md`, `references/geometric-detail-proof.md`, `references/geometry-fidelity-lock.md`, `references/target-profiles.md`, `references/blender-execution.md`, `references/benchmark-plan.md`.

## V1.3 enhancement routing (no ninth skill)
- **Reference Analyst / G1**: use `scripts/reference_alignment.py` for 2D landmark fit only when orthographic evidence exists (`references/reference-alignment-v13.md`). Do not derive 3D camera calibration from a photo.
- **Geometry Architect / G2**: author version 1.3 recipes and execute `build-recipe` via Blender Bridge for deterministic parts (`references/modeling-ops-v13.md`); for edits use snapshot-gated `apply-repair` (`references/geometry-repair-v13.md`). The auditor must inspect each candidate, not the creator.
- **Sculpt & Surface / G3**: tube-to-mesh, Boolean groove and `quilt_panel` evaluated vertex displacement are concrete geometry primitives. Require export persistence and clay/wireframe evidence (`references/surface-geometry-v13.md`).
- **Assembly / G2–G5**: measure AABB broadphase clearance/proximity/centering (`references/assembly-v13.md`). `PASS_PROXY` is NOT a physical collision or engineering certificate.
- **Topology / G5**: evaluate `detail_budget.py` allocations before `create-lods` (`references/detail-lod-v13.md`). Protect all geometry-sensitive feature IDs and explicitly locked components from unapproved simplification.
- **Fidelity Auditor / G7**: compare fixed-camera before/after viewpoints with `regress_views.py` (`references/regression-v13.md`). This tests preserved appearance, not source-reference similarity. Continue independent G7 semantic inspection.
- **Materials and Export / G4–G8**: use `resolve_variant` rules then `build-variant`, producing only selected permitted combinations (`references/variants-v13.md`); verify actual exported files and visible parts in target engine.
- **Qualification / all**: log four real Blender benchmarks and compare against baseline through `benchmark_runner.py` (`references/benchmarks-v13.md`); no performance claims from unit tests alone.

Version 1.3 specification JSON is **additional** to the unchanged `project.json` schema 1.0. The actual model producer is Blender via `bpy` or authorized MCP, not the pure-Python validators. Never update a gate from metadata validation to visual approval without inspecting actual results. Maintain source backups, user-approved locks, and project-local output paths.


## V1.4 — Adaptive Intelligence Router (AIR) | task-level model/effort selection
- Read `references/air-orchestration-v14.md` for multiagent work. Keep the **same eight existing skills**, but route **each concrete task** independently via the Model Capability Registry; never permanently bind one model to a skill.
- Use five `domain_classes` (extra_basic, basic, medium, advanced, extra_advanced) and four supported effort levels (low, medium, high, extra_high), only after checking active runtime compatibility. Assess complexity, uncertainty, impact, error cost, multimodality, duration, budget and independent QA requirements per task.
- Preflight: validate catalog + task DAG, select a quality-eligible route before optimizing estimated cost/latency. Tools with deterministic validators should run **without LLM assignment**. `fixture.*` model entries are synthetic test fixtures, NOT actually available models or real prices. Production catalog starts empty until real capabilities are verified.
- Use `python scripts/air.py route ...` to create a **non-executing plan**; only an explicitly authorized host adapter can create subagents and change model/reasoning settings. In plain ChatGPT plugin sessions without host delegation, use one agent with an advisory task plan and do not claim a model swap or a spawned subagent. See `references/air-runtime-v14.md`.
- Parallelize only independent read-only work. Serialize all scene writes; for AIR-managed Blender bridge runs obtain/validate a cooperative scene lease and set `FORGE_AIR_MANAGED=1`. External Blender GUI/MCP writers must independently respect the lease. Continue G0-G8, Geometry Fidelity Lock, checkpoints and independent Fidelity Auditor: the AIR's predicted class or simulated benchmark does not approve art.
- Escalate by *failure cause*: QA defect -> higher capable route and targeted repair, tool failure -> fix tool, missing reference -> acquire evidence, scene scope violation -> rollback. Enforce max attempts, logged runtime cost/latency and hashes for independently reviewed benchmark records. See `references/air-performance-v14.md` and `references/air-concurrency-v14.md`.

## V1.5 — Geometric Construction Blueprint (GCB) | mandatory G1.5 for reference-based modeling
- Preserve the eight specialists, unchanged project.json schema 1.0 and all existing G0–G8 gates. Insert **G1.5** between G1 Reference and G2 Blockout for source-art reconstruction, multipart shapes and animated/stylized assets; adapt technical-sheet count to complexity, never generate arbitrary pictures for simple objects. Read `references/construction-blueprint-v15.md` and `references/construction-schema-v15.json`.
- Reference Analyst (G1) records each observed/inferred/unknown component, view/calibration confidence and missing surfaces. Geometry Architect (G1.5 producer) converts this ledger into ONE numeric `planning/gcb/gcb_spec.json`: stable part IDs, allowed primitive/custom mesh data, dimensions, positions, rotations, pivots, attachment anchors, scene units, required steps and physical/relative scale caveats.
- Run `python scripts/gcb.py validate <spec.json>`, then `python scripts/gcb.py prepare <spec.json> --out <project>/planning/gcb` to create deterministic dimensioned SVG/optional PNG construction sheets, cumulative step guide, exploded schematic, JSON and Codex handoff. The numeric JSON alone is the authority for assembly coordinates; generated sheets must never be used to re-infer measurements or replace the original artistic likeness source.
- Where real Blender is available, use `blender --background --python scripts/gcb_blender.py -- --spec <project>/planning/gcb/gcb_spec.json --out <project>/work/gcb_blockout` for **temporary** blockout + fixed-camera renders before final G2 detailed modeling. Keep original `.blend` intact and serialize scene writes per AIR lease policy.
- Fidelity Auditor independently examines original reference, GCB technical plates, part inventory, dimensions/anchors, omissions/duplicates, calibrated silhouette and actual Blender renders. No Blender route means planning only. `SPEC_VALIDATED_PENDING_VISUAL_QA` is NOT G1.5 approved; block G2 on rejected art fit or missing mandatory components; revise only affected IDs and regenerate images from updated JSON.
- Rigging Specialist consumes documented GCB pivots for articulated targets but still must build/test rigs and animation clips. GCB metadata does not prove rigging, UV, materials, export persistence or Roblox Studio compatibility.
- AIR may allocate model/effort independently to source analysis, spatial planning and independent audit; deterministic validator/image scripts do not need an LLM. GCB adds **no ninth skill**, no forced extra agents, no automatic provider/model switching and no 100%-fidelity promise.
- Run `python -m unittest discover -s tests -p 'test_gcb_v15.py' -v` for GCB-only regression tests. Real Blender and Roblox validation require their respective live environments; do not present pure-Python tests as those integration checks.


## V1.6 — Adaptive Source File Intake (G0-F, before G1/G1.5)
- On each new model/reconstruction/edit request, read `references/gcb-file-intake-v16.md` and inspect **conversation attachments and existing accessible files first**. Collect all necessary assets in a single, purpose-specific request (essential, recommended, text information), not a chain of avoidable questions. Never request another upload of an already accessible image; retain user-supplied files unchanged.
- `reference_model`: require at least one actual concept art, orthographic picture, PDF drawing, or usable 3D source. `edit_existing`: require a source model or verified authorized scene. `original_model`: a clear text brief suffices; reference files are not universally required. Real-world exact sizes require credible numeric measurements/calibrated drawings; a single uncalibrated view supports only relative geometry. Existing rig retargeting requires the destination rig or a bone hierarchy specification.
- When present, classify assets by stable IDs, view, projection, trust, visibility and whether access was actually verified. Request extra views, closeups, materials and movement references **only if relevant**; they improve fidelity but are not automatically essential. If the user states a file is unavailable, record that answer and do not repeatedly request it. Keep original art as the authoritative visual reference.
- For local Codex projects create `planning/gcb/intake_manifest.json` then run `python scripts/gcb_intake.py planning/gcb/intake_manifest.json --root . --out planning/gcb/intake`. Exit 3 / `AWAITING_REQUIRED_INPUT` blocks reference authoring; exit 0 with `READY_WITH_ASSUMPTIONS` allows G1 but does not establish fidelity. The CLI only verifies local file paths/metadata; ChatGPT attachments are verified conversationally by actual inspection, not fictitiously marked as local.
- Before `scripts/gcb.py prepare` where local tooling exists, pass `--intake-report planning/gcb/intake/intake_report.json` to enforce the G0-F decision; never forge `ready_for_g1`. A successful intake is not G1, G1.5, G7 or Blender execution. The original GCB JSON format, eight specialist skills, AIR task routing and G0-G8 gates remain unchanged.


## V1.7 — Anatomy-aware Reference Image Generation and QA (conditional G1-R)
- Trigger **only** when the user explicitly asks to generate/draw/create visual reference images for building a 3D asset (including "generate everything Codex needs"). Do not invent images as a mandatory prerequisite when the user requested only a model, edit, technical GCB sheet, or audit. If generation is requested and the runtime has no image generation/editing tool, provide the structured reference plan with status `NOT_GENERATED`; do not claim images exist.
- After G0-F, read `references/reference-image-generation-v17.md`. Before generating, lock subject identity, art direction, invariant part inventory/unique IDs, limb/jaw/wing/tail counts, body-support/contact assumptions, mechanical/anatomical joint logic, separate moving meshes, occlusion and uncertain surfaces. Fictional/Roblox/Bloxy anatomy needs **internally coherent** geometry, not an imposed biological realism style; Bloxy is not low-poly.
- For requested new concept art, generate a clear primary reference before derived orthographic/multi-angle views. User-supplied original artwork always stays immutable and authoritative; generated missing angles are `inferred` until approved. For original concepts without supplied artwork, the selected approved generated design becomes a **design** reference, never measured physical evidence. Do not mark generated 2D dimensions as calibrated world mm.
- Produce only the views/closeups required for construction, with fixed IDs and consistent anatomy, silhouette, markings, joints and color/detail language. Prefer neutral uncluttered orthos and local joint closeups over decorative views; annotate uncertainty and parts hidden in original images.
- Independently inspect the **actual generated image pixels**, not only the text prompt, for count/presence of structures, volume/load path, joint ranges, wing/mandible pivots, no accidental fusion/duplicates/floating pieces, consistent projections, possible mesh construction and manageable 3D detailing. Log affected `part_id`, evidence/image ID, severity, and correction. Reject critical errors; iterate targeted changes and re-review without silently modifying protected original art.
- When local files exist, record generated image metadata + per-part construction operations + scene/anatomy visual-review evidence in `planning/gcb/reference_images/image_reference_qa.json`; run `python scripts/gcb_image_qa.py validate ... --root <project_root> [--gcb-spec <spec.json>]`. The script checks structural/handoff consistency and local file signatures, **not actual anatomical correctness**. Save its QA report, require an independent visual verdict before any `ready_for_gcb` assertion. No visible generated images means QA stays `PENDING_VISUAL_QA` or `NOT_GENERATED`.
- If GCB is built from newly generated images, pass approved report via `python scripts/gcb.py prepare <spec.json> --out ... --reference-qa-report <reference_image_qa_report.json>` after the images have been independently reviewed. Existing GCB SVG/PNG technical sheets remain deterministically generated from the numeric JSON; free-form image generation cannot replace their dimensions. Continue G1.5 and G2-G8 gates normally; never promise 100% anatomical/artistic fidelity from an image model.

- Before choosing operators/modifiers/material/node/rig/export techniques for G1.5–G8, read `references/blender-atlas-routing-v18.md` and query `references/blender-atlas-index-v18.json` via `scripts/blender_tool_router.py` **only for the current task**. The original PDF is `assets/blender-atlas/Atlas_Blender_5_2_2_LTS_407_Ferramentas_e_11_Abas.pdf`; do not load all 85 pages into each request.
- The index preserves all 407 curated entries with fields (what, applications, when, reason, proper use, hack) and PDF page refs, plus 16 chapters and 11 workspaces. This is a **secondary user reference**, not the exhaustive Blender API; check actual installed version and `bpy` names, parameters and execution context using official docs or the live runtime.
- Pick the **simplest effective** method preserving art fidelity, required true geometry, performance, editability and export. Document tool ID/page, reason/alternatives and target caveats. `bpy.data` operations are often safer than context-dependent `bpy.ops`; PDF UI shortcuts are not Python operator IDs.
- GCB v1.8 `scripts/gcb.py prepare` generates an **advisory** `blender_tool_plan.json` and `.md` automatically when the atlas index is valid, linked from `gcb_handoff.md`. This does not alter `gcb_spec.json`, does not execute Blender and never passes G1.5/G7/Export gates.
- If the index is missing or source SHA-256 mismatches, report the problem and abstain from claiming an atlas recommendation. If the installed Blender differs from the atlas's declared 5.2.2 version, verify each technique's current API manually. All prior G0-F/G1-R/AIR/Geometry Fidelity Lock restrictions continue unchanged; no ninth skill is created.
